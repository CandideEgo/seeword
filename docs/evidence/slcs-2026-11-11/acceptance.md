## 签发方工具与浏览器发布走查（2026-11-12 补记）

原先仓库里没有任何东西能产出发布收据：课程导入、审核都做得了，但「发布为当前版」要求粘一个 Ed25519 JWT，而签发私钥按设计不在站点里。结果是**第一门课程永远发不出去**。现在补上了：

- `backend/scripts/sign_lesson_receipt.py`：`keygen` 生成密钥对并把站点侧配置打印出来（私钥拒绝写进仓库）；`claims` 只读打印会被签进去的声明；`sign` 输出可粘贴的 token（JWT 走 stdout，声明摘要走 stderr）。它不 import `app.*`，只用一条只读连接查五个字段。
- `backend/tests/test_lesson_receipt_signer.py`：14 项，钉住「签发方与站点验签器必须一致」——同一 token 过 `verify_lesson_receipt`、改任一声明即 422、未知 kid、超出站点上限的 900s、换签发方都拒；`keygen` 不覆盖已有私钥也不许写进仓库。
- `backend/scripts/smoke_lesson_publication.py`：在真实 Postgres 上把签发脚本当**子进程**调用，跑完整条链路。

### 嵌入模式的失败态（本轮新增实测）

嵌入**正样本**仍缺：roadmap 要求先核对署名、字幕授权与平台嵌入条件，我没有可核验的材料，不自己造一份。

但「嵌入失败」是 [02 产品需求](../../slcs/02-product-requirements.md) 要求覆盖的四类状态之一，用一份 `provider_embed` 探测包（`source_url` 指向不存在的视频 ID，审核结论明确写着「嵌入失败态走查样本」）可以真实验证。实测（1440×900，ego-browser）：

| 时刻                                  | 结果                                                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 页面加载                              | 显示「YouTube 0:49」与「加载 YouTube 播放器」按钮，**12 段双语字幕已可读**                                        |
| 点加载后 14 秒（播放器自身 9 秒超时） | `role=status` 出现「嵌入播放暂不可用」，按钮变「重试嵌入」                                                        |
| 失败后字幕                            | 仍是 12 段，`Welcome to Wikisource!` 等原文与译文**照常可读**——正是需求要求的「嵌入失败时双语字幕与释义仍可阅读」 |

这次没能截到图：失败态页面里残留的 YouTube iframe 让 `Page.captureScreenshot` 超时（CDP 请求 30 秒未返回）。行为结论来自 DOM 状态读取，不是截图。

截图：[`word-card.png`](word-card.png)（桌面，词卡状态）、[`lesson-mobile.png`](lesson-mobile.png)（390px）。环境重建步骤见 [`isolated-environment.md`](isolated-environment.md)。

**本轮修掉的两个签发方缺陷**：`build_claims` 原先直接从行里取 `review_sha256`（该字段在嵌套的 `review` JSON 里，真实库上必然 `KeyError`）；省略 `--revision-id` 时只查 `candidate`，于是「已撤回待恢复」这种同样需要收据的路径会误报找不到修订。

**走查中确认不算缺陷的一点，与一条工具限制**：

1. 用途审核的复选框是 13×13 px 的原生方框，但**整行 `<label>` 可点**（625×20 px）。在 1440×900 视口下用真实鼠标点方框本身也成功（`after real click on box: true`）。先前记成「点不中」是误判：那次浏览器窗口被缩到 135×75，坐标早已落在视口外。
2. `ego-browser` 没有直接的视口设置方法，但 `page.cdp("Emulation.setDeviceMetricsOverride", …)` 可用；只要先设好视口，滚动容器内的按钮就正常可点。后续走查请先设 1440×900 或 390×844，不要沿用上一个任务遗留的窗口尺寸。
