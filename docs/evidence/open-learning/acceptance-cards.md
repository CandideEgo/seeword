## 1. 先固定测试卡，再执行

每阶段开始前必须形成验收卡；阶段门不得保留“待定人数／数量／阈值”，更不能完成后降低门槛使结果通过。调整试验设计须记录原因和新版本，不能覆盖原失败记录。

| 字段       | 必填内容                                                                               |
| ---------- | -------------------------------------------------------------------------------------- |
| 标识与状态 | 卡片编号、所属阶段、设计版本、拟议／已确认／执行中／已判定；确认者和日期               |
| 对象与规模 | 材料／修订／段／语境出现项数量，查询数、操作次数、参与者与环境数量；明确真实与合成数据 |
| 任务与步骤 | 初始状态、动作、预期输出、失败与恢复路径；参与者可获得什么说明                         |
| 指标与目标 | 正确性断言、任务完成目标、求助与耗时口径、性能目标及测量条件；数值与理由               |
| 人员与判定 | 执行者、记录者和验收负责人；独立于实现者的参与情况，以及无法独立时的限制               |
| 证据与隐私 | 版本／提交、命令、环境、原始结果、截图或观察记录；公开与私密证据的存放边界             |
| 结论       | 通过／失败／未执行、实际分母、偏差、阻塞缺陷及复验记录；尚未执行时不填通过             |

证据按实际活动放在本目录下的阶段目录，只有开始真实活动时才建立。阶段 `acceptance.md` 索引原始结果；设计卡和执行结果分开标注。含个人数据、token 或不可再分发正文的原始证据存于受控位置，仓库仅留脱敏结论与可追溯编号。

`docs/evidence/open-learning/` 与已有 `docs/evidence/astryx-integration/` 同为仓库根 `docs/evidence/` 的直接子目录；这里的 `../../` 返回 `docs/`，不是返回仓库根。

## 2. 待确认的规模与演练起点

**以下保留 v0.2 的建议，仅供 P0 估算，不是已承诺资源、科学最佳规模或通过标准。** 无法招募时可先内部冒烟，但不能把自测改称独立验收。D05 确认后把适用参数写入对应阶段卡，再将本表相应项改为指向该卡，避免两处维护确定值。

| 阶段 | 建议起点                                                                                | 演练与主要记录                                                                                                    |
| ---- | --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| P0   | 三项阻塞决策逐项有结论；P1–P3 测试卡明确规模与负责人，P4–P5 明确最晚细化时间            | 保留／缺失／不做与消费者逐项盘点；缺少许可结论或验收参数不记通过                                                  |
| P1   | 约 8–12 份短材料；按所选目标拟定难度覆盖；逐份清点实际语境出现项数量，不以重复词条凑数  | 至少 1 名未参与实现者完成 2 次局部纠错；至少各 1 次新修订发布、当前版回退、撤回与重新获准恢复；记录操作和审核工时 |
| P2   | 建议先招募 3–5 名符合目标条件的学习者，每人完成同一核心任务；时长上限与完成目标事先确定 | 记录成功分母、求助、误操作、耗时、定位与恢复；导出／注销另用隔离账号测试                                          |
| P3   | 至少 1 名未参与实现的接入者；本地包、在线授权路径分别演练；规模和查询集沿用检索测试卡   | 记录安装到首次成功查询时间、缺失说明、网站／工具定位一致性和权限负例；修改文档后重新执行受影响步骤                |
| P4   | 网站与第三方各走 1 次同类操作；每个写动作覆盖重复、并发、越权和撤权，次数在卡中固定     | 以数据库事实和状态变化判定，不只看 HTTP 成功；记录允许动作、确认依据和重放结果                                    |
| P5   | 至少 1 次非开发者日常环境的干净安装，覆盖确认的版本组合                                 | 无官方私密配置完成基础路径；记录安装／交接工时、兼容结果和待处理风险，再决定扩量                                  |

语境出现项总量、查询集规模、成功率目标、工时预算和性能目标仍待确认。表中的少量参与者只能发现流程问题，不能支撑普遍教学效果结论。保留 P4／P5 原有建议不表示启动其设计或实施。
