3. **最大的阻塞不是代码。** 根 `LICENSE` 声明专有且禁止再分发，与「第三方能基于同一份数据做自己的学习产品」直接冲突。

## 后续怎么做

按依赖排序，不是按工作量排序。每一步的验收标准写在 [06](06-implementation-roadmap.md)，此处只列顺序与前置。

### 第 1 步：读取器独立化（现在就能做，不依赖任何决定）

这是唯一既不碰生产代码、又不依赖许可的问题。完成后阶段 0 的 CLI 部分即可验收。

| 动作                                                                                                    | 现状                                          |
| ------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `app/slcs` 改为独立包，去掉 `__main__.py` 的绝对 `from app.slcs`                                        | 现在换目录即 `ModuleNotFoundError`            |
| `_WORD` 改为公开 tokenizer                                                                              | 现在私有，且与另外四套词边界并存              |
| 指纹算法从 `services/video_learning_material.py` 并入发行包，与 `teaching/content.py::stable_hash` 合并 | 现在同一 canonical JSON 有两份实现            |
| CLI 加 `--json`、`resolve`、`fingerprint`，退出码回到 0/1                                               | 现在传目录抛 `[Errno 13]`，argparse 用 exit 2 |
| 加一条「读取器不得 import `app.*`」的测试                                                               | 现在这条隔离只是偶然成立，没有守护            |

**验收**：在仓库外的空目录里，用独立虚拟环境执行 CLI，能校验参考包并输出结构化结果；发行包内 `grep -rn "from app"` 零命中（今天只有 `__main__.py` 一行，见 [03](03-system-architecture.md)）。

### 第 2 步：让验收从「自证」变成「可证」

现在负例只活在 pytest 里，参考 digest 由同一实现重算，CI 门还埋在带 Postgres/Redis 的 job 内，且 markdown-only 改动会跳过它。

| 动作                                                 | 为什么                                     |
| ---------------------------------------------------- | ------------------------------------------ |
| 负例落成 `docs/slcs/examples/invalid/*.json` fixture | 第三方能直接拿去做一致性测试               |
| 参考 digest 写成字面断言                             | 现在的写法实现一致就通过，改坏了也未必发现 |
| CI 拆出独立 job，不装数据库                          | 校验器只依赖 pydantic，不该要 Postgres     |
| 处理 `paths-ignore: **/*.md`                         | 纯文档改动会整体跳过 SLCS 门               |

**验收**：故意把一个负例改成合法包，测试必须失败；故意改一位 digest，测试必须失败。

### 第 3 步：站点侧前置（阶段 1 之前）

[03](03-system-architecture.md) 的「必须先解决」有 12 条。真正卡顺序的是前四条，其余可并行：

1. **课程身份与修订模型** —— `lesson_id` + revision + `fingerprint_version` + status + 可清空的当前版指针。不能建在 `videos` 行上（URL 护栏与发布资格都拒），也不能沿用 `published_snapshot`。
2. **学习单位换键** —— 上节那两个静默缺陷。先定键策略，再动任何课程页面。
3. **披露边界落到数据** —— 视频侧没有 rights 列，SLCS `Rights` 也没有逐用途权限。抄 `rights_policy` / `may_disclose`。
4. **撤回可达性统一路径** —— 进程内 60s 媒体缓存下架不清、nginx 图片缓存、`word_ai_notes` 无失效、`teaching.withdraw` 不清指针。撤回演练前必须有一条覆盖四层的路径。

### 第 4 步：阶段 0 的外部验收

许可定了之后：独立客户端离线读取参考包、CLI 输出结构化结果、stdio MCP 在真实宿主里查询词义并回跳到原句。**MCP SDK 目前不在任何 requirements 里**，生产镜像也没有，本地工具需自带。

## 已知陷阱

写给下一个接手的人，都是实测过的，不要重新踩：

- **Windows 上每个 Python 进程都要 `PYTHONUTF8=1`**，否则读 UTF-8 的 `.env` 直接 `UnicodeDecodeError: 'gbk'`。
- **`python -m app.slcs schema` 的输出经 shell 管道会转 CRLF**，别用字节 diff 判等，用 JSON 比较。
- **本机 DNS 代理把域名解析到 `198.18.0.x`**，`is_private` 为真，会让 URL 护栏把合法域名判成内网。判断护栏行为前先看 `_resolve_ips` 返回什么。
- **`_is_blocked_ip` 漏 CGNAT**（`100.100.100.200` 不被拦）；SLCS 校验器本身也不拒绝私网与回环 `source_url`。将来若服务端要解引用包内 URL，这半必须重写。
- **`mediaUrl()` 的 token 分支先于绝对 URL 分支**：`mediaUrl(thirdPartyUrl, {withToken: true})` 会把 JWT 拼到第三方主机。蓝图已定「深链不携带媒体访问 token」，实现里还没落实。
- **`publicError` 会吃掉 SLCS 的字段路径诊断**，422 的结构化 `detail[]` 在 `createApiClient` 里先被拍平成 `"; "` 串。做导入/审核界面前要先建结构化通道。
- **`_VIDEO_ACCESS_CACHE` 是进程内 60s 且下架不清**，多 worker 各有窗口。任何撤回演练都要考虑它。
