# SeeWord 开放视频学习后续设计

先让外部贡献者交付一份可审核的视频学习包，让学习者打开原片、读双语字幕、点重点词并回到原句。随后让 V2 导师引用同一份材料，验证内容能服务于观看和教学两个入口。本文记录建议顺序，现行文件契约和 V2 验收口径见各自文档。 [SLCS v0.1](README.md) · [V2 后端实施主线](../../refactor-blueprint/docs/execution.md)

## 从贡献到发布

- **贡献者用 Git PR 维护学习包。** 从少量素材开始，提供示例和离线校验命令，CI 用同一个校验器报告字段路径。维护者核对原文、译文、词汇锚点和实际授权，分别记录原视频、字幕、译文和词汇的依据。仓库保存学习数据和原片链接，媒体由原站提供。待首批贡献跑通，再评估是否拆独立内容仓库。
- **应用按已发布修订读取。** 从审核通过的提交导入候选版，维护者显式发布后切换当前版本。把 `lesson_id` 作为长期身份，用内容指纹识别重复包，用不可变修订标识固定一次发布。参考 V2 的审核和操作回执设计。现有教学发布服务围绕考试题与揭晓规则，视频通过独立适配进入材料层。 [V2 材料域设计](../../refactor-blueprint/docs/architecture.md#2-模块与数据归属)
- **发布与撤回经过同一个可见性入口。** 观看页、导师和未来的外部工具从这里解析材料。撤回后停止提供正文、字幕和词汇语境，并清理关联缓存。旧学习记录可以保留引用和状态，用户打开时看到材料已不可用。相同包重复导入应得到同一候选版，发布失败应保留当前可用版本。

## 先验证观看与点词

首批用两份已人工复核的样本覆盖两种媒体模式。现有维基文库参考包用于外链，发布前补做逐段听审。另选一份有可核查授权的官方可嵌入样本，验证站内逐词高亮、跳到原句及嵌入失败后的回退。 [维基文库参考包](examples/welcome-to-wikisource.json)

| 场景 | 验收 |
| --- | --- |
| 原站外链 | 学习者能在站内读字幕和查看语境词条，并从明确的入口打开原片。同步控件只在客户端能取得播放时间时出现。 |
| 官方嵌入 | 用播放时钟驱动双语字幕与词级高亮。未对齐的重点词仍可查看释义和定位整句。播放失效时提示原因并提供原片链接，仍获准提供的学习数据可继续阅读。 |
| 发布与修订 | 从 Git PR 提交到审核、发布、观看、撤回各走一次。重复导入、发布失败、旧链接和缓存分别做回归。 |

观看层可复用现有 YouTube 播放适配器和字幕交互。先以小目录连接现有站点，再按实际投稿和学习数据决定是否建设独立发现页。 [YouTube 播放适配器](../../frontend/src/lib/youtubePlayer.ts)

## 再接 V2 导师与复习

1. **先做一条可验证的导师动作。** 学习者选中重点词，导师解释它在当前句里的意思，回复引用可回到该原句。后端从获准的已发布修订读取相关字幕与词汇语境，用材料类型、修订、段 ID 和词 ID 标识来源。恢复历史时重新核对可见性。 [V2 教学组件与动作方向](../../refactor-blueprint/docs/agent-plan.md)
2. **再把同一个词关联到多处真实语境。** 词条保留每次出现的来源。新版字幕保留未改动的段和词 ID，无法确认的旧锚点明确标为失效，由编辑核对后再迁移。复用现有收词入口和复习事实，跨来源复习与调度调整按 V2 既有验收推进。
3. **最后开放更多入口。** 贡献者工具先解决已授权素材的导出、校验和预览。等站内材料读取、权限和撤回行为稳定，再考虑公开目录、外部 Agent 读取和多语种扩展。
