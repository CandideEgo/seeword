# 01 Product Vision · 产品愿景

SeeWord 将作为 SLCS 的第一个参考实现。目标是让一份视频学习包能在 SeeWord、独立客户端和用户自带的 Agent 中使用。学习者在任一入口看到词义，都能找到这条解释所依据的原句。[SLCS 规范](README.md)

## 服务对象

| 对象               | 要完成的事                                                                          |
| ------------------ | ----------------------------------------------------------------------------------- |
| 英语学习者         | 结合原片读双语字幕、查语境词义、回到原句，再把词带入复习。                          |
| 内容贡献者与维护者 | 为获准使用的视频整理学习材料，提交修订并跟踪审核、发布或撤回。                      |
| 独立开发者         | 依据规范与参考包在自己的客户端实现字幕阅读、查词和原句定位。                        |
| 自带 Agent 的用户  | 把自己选择的学习包交给本地 CLI 或 MCP，在配置了自己模型 API 的 Agent 中按原句提问。 |

## 三个开放方向

- **开放标准**。让开发者从规范、Schema 和一致性样例实现独立读取，复现同一份材料的词义和锚点。
- **开放内容**。让社区在授权范围内创建、分享和维护学习包，后续修订保留可追溯的出处。[社区治理](05-community-governance.md)
- **开放学习能力**。这是长期重点，也是本方案与“做一个英语学习站”的分界。SeeWord 只做官方参考实现，读取与定位能力应当离开网站同样可用：第三方产品和用户自带的 Agent 围绕同一份材料设计自己的教学体验。优先验证查词、语境解释和原句回跳三件事，它们是任何学习产品都要重新做一遍的最小集合。

三者的关系是：标准让数据站得住，内容让数据有得用，学习能力让数据不必依附于某一个站点。若站点变成唯一可用的消费方式，前两项就失去意义。

## 不做什么

- 不做封闭平台。学习包与读取能力不以 SeeWord 账号、SeeWord 服务或 SeeWord 界面为前提。
- 不做托管式教学 API 生意。首期不提供他人代持模型密钥、代理模型调用或按量计费。
- 不承载未获授权的素材。站内不做“先上车后补票”的公开目录。
- 不因开放标准而重构现有生产链路；迁移按 [系统架构](03-system-architecture.md) 的保留／抽离／重设计逐段进行。

## 首期范围与成功条件

首期聚焦英语视频与简体中文释义，覆盖一份完整学习包的独立消费和站内参考体验。站内采用登录后的小目录，外部采用离线客户端和本地工具。公开目录、多语种、独立内容仓库和跨宿主学习状态同步留待后续评估。[实施路线](06-implementation-roadmap.md)

核心指标是第三方完成一次有原句出处的学习任务。具体表现是独立客户端能打开参考包、查到语境词义并定位原句，同时用户可用自己的 Agent 对同一词义提问，获得能解析回同一原句的引用。[产品需求](02-product-requirements.md)
