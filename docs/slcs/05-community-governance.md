# 05 Community Governance · 社区治理

以下是 SLCS 试点拟采用的治理规则。贡献者提供来源与授权证据，维护者审核内容和用途、执行发布或撤回并记录回执。学习者可以通过课程页的来源和署名核对材料，并向维护者报告内容错误或权利问题。

## 贡献与用途审核

提交公开 Git PR 前，贡献者先运行离线校验，再核对 PR 中每项材料及署名信息的公开再分发依据。PR 附学习包、来源和改动说明、逐段听审结果。包记录原片链接，媒体由来源站点提供。证据不足的材料先通过私下渠道向维护者提交线索，待核对后再进入公开 PR。 [学习包与校验命令](README.md)

| 审核对象 | 贡献者提供的证据与维护者核对事项                                                                     |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 原视频   | 记录原片地址、署名、权利依据和站内使用方式。外链与官方嵌入分别核对，采用嵌入时另核对来源平台的条件。 |
| 字幕     | 记录原文来源、转录与时间标注的作者或制作方式，核对站内展示和公开再分发范围。逐段听审原文及时间轴。   |
| 翻译     | 记录译文来源、署名和改编依据，核对站内展示和公开再分发范围。逐段检查译文与原句的对应。               |
| 词汇     | 记录释义来源、署名和改编依据，核对站内展示和公开再分发范围。检查词义与原句语境、词锚点的对应。       |

维护者按修订和用途记录证据、结论及条件。向模型披露另行核对允许提供的材料、范围和适用条件，站内导师仅取得该用途获准的语境。用户自带 Agent 时，本地工具把所选包的只读结果交给宿主，宿主在获准范围内向用户配置的模型 API 提供语境。依据缺失或存在争议时，暂停该用途。

CI 和站内导入使用参考校验器检查结构、时间和引用。校验结果作为人工审核的输入，维护者仍需核对署名、实际授权及内容质量。包内 `provenance` 保留贡献者的声明，审核结果由发布记录另行保存。 [数据契约](README.md) · [披露边界](03-system-architecture.md)

## 角色与权限

| 角色   | 可以做什么                                   | 不能做什么                               |
| ------ | -------------------------------------------- | ---------------------------------------- |
| 贡献者 | 提交 PR、补充来源与授权证据、回应审核意见    | 直接导入候选修订或发布                   |
| 维护者 | 审核、导入候选修订、显式发布、撤回、记录回执 | 跳过授权证据发布；代替权利人作出许可声明 |
| 学习者 | 阅读已发布课程、报告内容或权利问题           | 修改材料                                 |

首批至少需要一名维护者；增加到两人以上时，同时约定审核留痕的存放位置、复核周期与冲突时的处置人。权限收紧时保留已有回执，不删除历史审核记录。

## 发布、修订与撤回

1. **审核与发布。** 维护者记录 PR 或提交、审核人、审核时间、用途结论和证据，将通过审核的包导入为候选修订。候选版仅供审核人员查看。维护者显式发布后，站内目录使用新当前版，发布回执记录操作者、时间、修订、来源提交和结果。
2. **修订。** 更正字幕、译文、词义或授权声明时，提交新修订，说明差异并复核受影响的用途。历史学习链接仍固定到原修订，并按该修订当前的可见性展示。 [版本与引用](03-system-architecture.md)
3. **撤回。** 维护者记录原因、范围、时间和操作者，停止站内提供该修订的正文、字幕和词汇语境，并清理关联缓存与历史恢复投影中的内容。历史保留引用和学习状态，入口显示材料已不可用。撤回当前版后，如需恢复课程，由维护者复核并显式发布可用修订。 [站内撤回验收](06-implementation-roadmap.md)

公开 Git 历史、分支、下载包和第三方副本各有独立的传播与处置流程。站内撤回控制 SeeWord 的访问，公开副本由对应托管方或持有方处理。

## 规范版本管理

- **谁改。** 规范正文、JSON Schema、参考校验器与一致性样例改动同一批提交，由维护者审核；涉及对外发布范围的改动同时走上一节的用途审核。
- **怎么发。** `schema_version` 是包的契约版本，当前只接受 `0.1.0`。读取器拒绝未知字段（`extra="forbid"`），所以新增字段无论是否必填都是契约变更，必须升版本：先让读取器接受新版本，再发布含新字段的示例，避免旧工具读到新包。
- **指纹。** 任何会改变同一份包指纹的契约改动，必须显式递增 `fingerprint_version`，让已存修订的摘要失效可见，而不是悄悄改变既有摘要的含义。 [指纹计算](README.md)
- **样例即契约。** 每次改契约，一致性样例和参考包的负例同时更新；CI 用同一校验器校验参考包，样例与生成出的 Schema 必须与提交的文件一致。 [校验与一致性样例](README.md)
- **废弃。** 版本废弃先标记、后移除，至少保留一个版本的读取支持，并在一致性样例中保留一条旧版本被拒绝或接受的用例。

## 对外分发

仓库根许可声明软件和关联文档为专有。对外分发前，由权利人分别确认规范正文、JSON Schema、参考校验器与学习工具、示例学习包的许可、适用范围和署名方式，并随各自的分发产物提供。Wikisource 参考包中的 CC BY-SA 4.0 为该包的来源声明，示例的发布仍按本页流程核对。 [仓库许可](../../LICENSE) · [参考包声明](examples/welcome-to-wikisource.json)
