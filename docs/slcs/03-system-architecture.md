# 03 System Architecture · 系统架构

## 现状审计

基线为仓库提交 `66070300`。审计按十个子系统展开：内容生产管线、字幕与重切、播放与文稿、修订与发布、导师与 Agent、词汇与复习、听力和考试、SLCS 读取器、前端壳层、媒体与鉴权。每条结论都由一次独立复核重新打开文件核对路径与符号，再对「保留／抽离／重设计／退役」的决定做一次反驳；复核推翻的结论已按复核结果修正，存疑项列在「未验证」。

站内 SLCS 发布、学习页、视频导师、本地学习 CLI 与 stdio MCP 已按阶段 0–4 实现（代码在 `docs/slcs-six-docs`，未部署生产，未对业务库执行迁移）。实现清单与逐项验收见 [交接](handover-2026-11-11.md)；本页审计结论仍描述基线 `66070300` 的代码，不代表新实现已验收。

### 保留

保留的前提是该能力与「学习单位是课程还是视频」无关；任何仍以 `videos.id` 为键的能力，在课程接入时都要单独过一遍。

### 抽离

抽离指把能力从站点耦合里摘出来，而不是另写一份。

| 能力                   | 要抽离的能力                                                                                                                                                                                                                                      | 站点耦合与缺口                                                                                                                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SLCS 包契约与校验      | `backend/app/slcs/__init__.py`：`LearningPack`／`Media`／`Token`／`Segment`／`VocabularyEntry`、`_check_embed`／`_check_segment`／`_check_pack`、`load_pack`、`json_schema`、`FINGERPRINT_VERSION`                                                | 运行时只加载标准库与 pydantic，零其它 `app.*` 模块，这是最有价值的性质。缺口：`__main__.py` 用绝对 `from app.slcs`，改名成独立包后 `python -m` 直接 `ModuleNotFoundError`；`_WORD` 私有；无 `[project]`／`py.typed`／console_scripts；没有任何测试守护这条 import 隔离 |
| 锚点解析与材料投影     | `services/video_learning_material.py::load_video_material`：`VocabularyOccurrence`、任一词未对齐即整段回退、canonical `{fingerprint_version, pack}` sha256                                                                                        | 无反向查询（锚点→出现），无「锚点不可用」结果类型；指纹算法留在 `services/` 而非发行包                                                                                                                                                                                 |

| 字区间锚点             | `models/teaching.py::ExamEvidence`：`unit="unicode_codepoint"`、`[start, end)`、`quote_hash`、`source_revision`，写入时校验 `0 <= start < end <= len(passage)` 并比对 `sha256(passage[start:end])`，读取侧由 `_immutable_fact` 守只追加           | 这是仓库里唯一「锚点 + 摘录指纹 + 来源修订」三元组，SLCS 的 token 偏移与「锚点是否仍有效」应复用它，而不是另立一套。规范侧已有同样口径：`docs/v2-technical-design-2026-10-31.md` 固定按 Unicode 码点半开区间并禁止前端用 UTF-16 下标切串                               |

### 退役

| 能力               | 为什么                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 站内 HTTP MCP 适配 | `integrations/mcp/server.py` 的 10 个 tool、streamable HTTP、CredentialGate 都按站内会话与教学上下文设计；仓库无 stdio 入口，SDK 不在任何 requirements、生产镜像也没有。SLCS 本地工具应是 `app/slcs` 之上独立的 DB-free 实现，只借命名与错误整形 |
| 前端离线包读取     | 无 service worker／manifest／IndexedDB，唯一 `type="file"` 是头像选择器。离线与 Agent 消费由 Python CLI + stdio MCP 承担，Web 壳只做在线登录阅读                                                                                                 |
| 视频审核快照机制   | `video_review_service._build_snapshot` 是单可变 blob、无版本/指纹/逐修订可见性、丢 `words`；实际不可达（无代码把 `review_status` 写成 `pending_review`），但四个读取方依赖它的分支，退役必须同批迁移读取方                                       |

### 可复用的既有实现

- `app/slcs` + `video_learning_material`：契约校验、锚点正向解析（含整段回退）、版本化指纹——本身就是模板，抽离即可，不要另写读取器。
- `models/teaching.py::ExamEvidence` + `content.py` 的区间与 `quote_hash` 校验：字区间锚点的唯一现成实现。
- `models/teaching.py::_immutable_content` 与 `v2_runtime.py::_immutable_block`：仅有的两处被 ORM 强制的只追加写法，课程修订与引用投影应照抄。
- `home_content` 的 `_allocate_revision` + `rollback_layout`：版本号分配（max+1 + SAVEPOINT）与「清空指针但保留可回退」。
- `teaching/content.py::may_disclose` + `dialogue.project`：三层权限映射，以及「撤回后旧输出也失效」的唯一实现。
- `teaching/publication.py::_claim` + `ContentPublicationOperation`：`UNIQUE(actor_id, operation_id)` + `request_hash` 的幂等回执。
- `teaching_runs.py` 与 `teaching_gateway.py`：租约围栏、事件游标、取消回收；模型准入、预算键、「绝不报零用量」。
- `question_exposure_service` 的 per-user upsert + for_update：复习幂等计数的现成机制。
- `subtitles.ts::findSubtitleIndex` + `useVideoPlayer.onTimeTick`：唯一成熟的「播放时间→内容位置」实现，毫秒化即可。
- `homeEditorial.highlightPhrase` + `HomeEditorialExpression.phrase`：多词跨度（如 `public domain`）唯一的现成高亮模型。
- `account_data.py` 导出时剥掉未交卷试卷的 `answer`／`explanation`：现成的「按权利裁剪导出」投影，课程导出应对齐而不是另写。
- `core/uploads.py::read_upload_bounded`：声明长度预检 + 分块上限，包导入走上传时应复用。

### 必须先解决

1. **许可与可分发工件。** 根 `LICENSE` 是专有声明，直接否定「第三方可复制」。先定规范、Schema、校验器与示例各自的许可，再补独立 requirements、`[project]`、py.typed 与入口点；否则抽离出来的是不能合法交付的产物。
2. **读取器边界收口。** 绝对 import、`_WORD` 私有、指纹留在 `services/`、无 import 隔离测试，四项一起改，并把 `video_learning_material` 并入同一发行包。
3. **课程身份与修订模型。** `lesson_id` + revision + `fingerprint_version` + status + 可清空的当前版指针。不能建在 `videos` 行上（发布资格与 URL 护栏都拒它），也不能沿用 `published_snapshot`。
4. **学习单位换键。** `learning_records`（`UNIQUE(user_id, video_id)`、CASCADE）、`watch_progress_service`（无 `Video` 行即 `NotFoundError`）、`GET /continue` 与 `progress_percentage` 全部按 `videos.id` 键。课程接入前必须定：课程进度另建键，还是课程映射到一个 `videos` 行——后者会让删视频级联删掉学习历史。
5. **行为事件丢失课程归属。** `behavior_service.drop_unknown_video_ids` 会把找不到 `videos` 行的事件 `video_id` 置 NULL 并保留事件。周时长仍可按用户和日期聚合，课程归属、进度镜像和观看计数会丢失。课程接入需要显式关联课程修订。
6. **披露边界落到数据。** 视频侧没有 rights 列，SLCS `Rights` 也没有逐用途权限。先抄 `rights_policy`／`may_disclose`，并决定 `content_receipts_enabled`（默认关，发布路径现为 503）是否随阶段一打开。
7. **锚点模型与分词唯一化。** 定段 id 稳定策略（重切现在每次新建 uuid4、回滚也新建）、token 偏移的派生层、`_WORD` 成为唯一公开 tokenizer。ASR 文本本身满足不了「保留标点与空白」，导出必须拒绝或修复。
8. **指纹规范与互操作。** 公开 `fingerprint()`、持久化 `fingerprint_version`、把 pydantic 的隐式默认写进规范。
9. **样例、负例与 CI 门。** 负例落成 fixture、digest 做字面断言、门拆成不依赖外部服务的 job，并处理 markdown-only 改动跳过门的问题。
10. **撤回可达性统一路径。** `_VIDEO_ACCESS_CACHE` 进程内 60s 且下架不清、nginx 图片缓存、`word_ai_notes` 无失效、teaching `withdraw` 不清指针——撤回演练前先定一条覆盖这四层的路径。
11. **导入的入口与护栏。** 目前没有包导入路由，因此也没有限流；应用内唯一的体积上限读取器只服务头像上传。新入口要带限流、体积上限与幂等（`BehaviorEvent.event_id`、`ContentPublicationOperation`、`PipelineDispatch` 三种既有写法择一，不要加第四种），并在 `health_monitor`／`pipeline_alerting` 注册探针——后者现在只认 `video_id`。
12. **导出与注销。** 新数据要同时进 `CSV_SECTIONS`、`EXPORT_ORDER`、`gather_export` 与 `tests/test_account_data.py` 的 `expected_sections`；有 `user_id` FK 的表由注销自动覆盖，但与教学表一样要先做缺表早退，否则未迁移的库上导出会 500。

### 未验证

- 审计与复核都只读代码，没有运行应用；`/lessons` 路由、模型与任务在基线里都不存在，浏览器行为无法验证。
- 复核推翻了一条审计结论：`asdict(material)` 实际可用，不抛 `TypeError`（已实测）。分词分歧也已按实测收窄：`U.S.A.` 与 `C++` 两侧一致，分歧只在组合附加符号、小数点与百分号的情形。

## 目标边界与数据流

| 边界            | 数据归属与流向                                                                                                                                                                                                                                                                                   |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| SLCS 文件与读取 | 已选文件 → 校验 → 只读材料 → 双语字幕、词义与时间锚点。文件契约以 [SLCS Specification](README.md) 为准。独立客户端可自行实现读取。                                                                                                                                                               |
| 本地 CLI 与 MCP | CLI 将读取和定位结果输出为结构化数据。MCP 经 stdio 暴露同一组只读能力，仅访问用户显式选定的包。返回的原句引用带课程 ID、内容指纹、段 ID 和词 ID，可在该包内复现位置。宿主负责配置模型 API、管理凭据与发起获准的模型请求。工具只解析文件和定位材料，包内文本及 URL 均作为数据处理。               |
| 站内发布与学习  | 通过审核的包 → 候选修订 → 显式发布 → 登录目录和独立学习入口。发布事务一起更新修订状态、课程当前版指针和操作回执。重复导入按内容指纹归并到同一候选或既有修订。                                                                                                                                    |
| 修订解析与披露  | `lesson_id` 归并同一课程，内容指纹识别同一包，站内修订 ID 固定一次材料版本。按修订访问时先判定当前可见性，再按展示或模型披露用途返回材料。发布新版后历史引用仍指向旧版。撤回当前版时清除当前版指针，后续发布由维护者显式决定。撤回后的站内历史只保留引用和学习状态，已有回复投影也需检查可见性。 |
| 学习状态        | 站内进度、收词、复习和导师历史由各学习域持有。新增引用携带材料类型、修订、段 ID 和词 ID，历史恢复经修订解析。SLCS 文件无需账号与学习状态即可消费。                                                                                                                                               |

首批沿用站内登录边界，以新增入口和默认关闭的试点开关接入。站内学习页、历史和导师共用修订可见性，首批材料投影避免跨请求缓存，撤回演练仍需验证已有缓存与客户端恢复路径。外部接入通过本地工具完成。既有领域事务与教学接口仍以 [V2 后端框架](../../refactor-blueprint/README.md) 为准。

## 技术选型

选型以“读取器不依赖站点、外部客户端可独立复现”为准，不引入新基础设施。

| 层         | 选择                                                                                                                 | 理由与约束                                                                                                                                                                                                                    |
| ---------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 文件契约   | 单文件 UTF-8 JSON + JSON Schema 2020-12                                                                              | 一个包可整体审阅、指纹可复现；跨字段规则留在校验器里，Schema 只描述结构。                                                                                                                                                     |
| 读取与校验 | Python 3.12 + Pydantic v2                                                                                            | 与后端同一运行时，复用现有依赖；`app.slcs` 只 import 标准库与 Pydantic，无 DB、无 Web 框架，第三方可整体复制。                                                                                                                |
| 材料投影   | 冻结 dataclass                                                                                                       | 只读、可哈希，调用方拿不到可变状态；指纹在投影时一次算出。                                                                                                                                                                    |
| 站内存储   | 现有 Postgres + Alembic；可借用 `home_content_*`、`subtitle_revisions` 与 V2 的 `teaching`／`content_publication` 表 | 不新建运行时；只追加版本与操作回执沿用已有唯一约束和事务语义。V2 表尚未对业务库执行迁移，依赖它们的阶段必须与迁移同批部署，缺表时入口保持惰性。                                                                               |
| 异步任务   | 现有 Celery                                                                                                          | 导入、预热与派发沿用既有队列，不引第二套调度。                                                                                                                                                                                |
| 本地工具   | Python CLI + stdio MCP                                                                                               | CLI 与 MCP 共用同一读取与定位函数；MCP 只在用户宿主进程内运行，不暴露网络端口。MCP 依赖 SDK，当前未进 `requirements-*.txt`，站内 HTTP MCP 由 `MCP_SDK_ENABLED`（默认关）门控；本地 stdio 适配须自带 SDK 并在阶段 0 单独取证。 |
| 站内前端   | 现有 Next.js 16 / React 19 / Tailwind v4                                                                             | 复用 `components/transcript` 与 `lib/youtubePlayer`，新增页面沿用用户壳样式与 `user-ui.css` 作用域。                                                                                                                          |
| 嵌入播放   | YouTube 官方 iframe 播放器                                                                                           | 包只声明 `provider_embed` 与视频 ID，客户端自行取播放时钟；失败退回外链。                                                                                                                                                     |

不选用的方案：另起一套内容数据库或 CMS（与站内修订重复）；让读取器依赖 SeeWord HTTP API（第三方离线客户端无法使用）；在包里存字幕文件或媒体副本（超出授权范围且无法校验）。
