# SeeWord 全项目审计与新人接手报告

**审计基线：`a93979c34dab7b8fb7a5493f76b63a28e58d48ac`。工作分支：`docs/slcs-six-docs`。日期：2026-11-14（北京时间）。**

## 先说结论

这个项目不是“一个播放视频的网站加几页单词表”，而是已经长成的**模块化单体学习系统**：视频生产、字幕编辑、词汇调度、试卷/听力判分、内容发布、账号生命周期，以及默认关闭的课程/教学/外部接入试点。前端、后端、GPU worker 和 SLCS 读取器有不同的运行边界。

**建议大幅整理，但不建议先推倒数据库、迁移链和核心学习事实。** 最值得动的是复杂用例的编排边界、任务可靠派发、前端观看页职责和试点功能的准入/契约；不是为了“目录看起来清爽”重写所有底座。

本轮已把历史文档体系从当前工作目录清出，保留最新大纲/P0/Astryx 证据，重写必要运行说明，并提供覆盖审计起点每个文件的清单。清理不代表大纲的 P0 已通过，更不代表代码完成了目标重构。

## 1. 给完全新人的概念翻译

- **前端**：用户点得到的网页。一个按钮常常只发请求，数据实际由后端保存。
- **后端/API**：根据身份和规则读写数据的服务，不是只要前端藏了按钮就安全。
- **数据库表/模型**：长期数据的结构；模型是代码中的描述，迁移是改变真实结构的历史步骤。
- **Redis**：不只有可丢的缓存，还承担工作队列、撤销令牌与运行协调，不能当垃圾目录清空。
- **worker/beat**：worker 执行后台工作，beat 按时间派发；二者不同。转录 GPU worker 还在另一运行组件/机器上。
- **事务**：一组写入一起成功或一起回滚。改函数位置时若拆开提交，可能“成绩存了、学习记录丢了”。
- **幂等**：重复点击或网络重试不应造成重复作答/记账。并不是任意函数叫两遍都天然安全。
- **outbox**：先在数据库记“必须派发这个任务”，再发送；失败还能补发。它不保证任务绝不重复。
- **revision/指纹/锚点**：修订固定“哪版内容”，指纹识别内容变化，锚点定位“哪句哪词”；不能只存材料 ID 就声称永远指回同一句。
- **DTO/schema**：前后端约定的数据形状。字段改名不是只改一页 UI 的小事。
- **fixture/mock**：测试素材/替身；可以证明规则，不能证明真实模型、真实 GPU 或生产网络已经跑通。
- **feature flag/profile**：控制能力是否启用/服务是否启动，不等于自动隔离数据库结构。
- **SLCS/MCP**：前者是学习包格式和独立读取工具；后者是外部宿主的协议入口。协议存在不代表第三方已获得任意读取/写入权限。

## 4. 审计发现：问题、取舍和证据分开

优先级是准备重构时的处理顺序，不声称这些问题已经在生产发生。下列业务风险本轮**只审计不改行为**，避免把文档清场偷换成未设计的业务重构。

### R01 · P1 · 视频回调缺处理代次，旧任务可影响新一轮

**代码依据**：[回调处理](../../backend/app/api/v1/internal.py)、[重试/重新触发](../../backend/app/services/video_seed_service.py)、[GPU 回调载荷](../../gpu-worker/gpu_worker/tasks.py)、[回调 schema](../../backend/app/schemas/video.py)。

任务/回调带 video_id、status、segments 等，没有一个与“这一次转录”绑定的 generation/attempt ID。回调只要共享密钥正确、视频当前为 processing、拿到去重锁就会继续。

**具体情形**：A 次转录超时，watchdog 标错；管理员在无字幕分支重试并开始 B 次转录；A 的迟到成功/错误回调此时到达，就可被当成本轮结果写入或把 B 标错。Redis 锁只能串行处理，不辨认新旧。

**后续做法**：以处理代次贯通 head、GPU 消息、回调、tail/outbox 与状态更新，使用数据库条件写入拒绝旧代次；同时处理在途旧消息的兼容。不能只加一个前端状态字段。静态链路确认；本轮合成探针的范围见验证页，不宣称真实跨机故障注入。

### R02 · P1（安全取舍）· Redis 故障时撤销与 refresh 单次消费降级放行

**代码依据**：[token_blacklist.py](../../backend/app/core/token_blacklist.py)、[refresh 路由](../../backend/app/api/v1/auth.py)、[鉴权依赖](../../backend/app/api/dependencies.py)。

`blacklist_token` 写失败只记录日志，`is_token_blacklisted` 出错返回 false，`claim_token_once` 出错返回 true。代码明确选择可用性优先，并非本轮发现一个未处理异常。

**影响**：故障期间已退出/撤销但未过期的 token 可能继续使用；被盗 refresh 的重放可能再次铸出后继链。改密/封禁的 DB 校验仍在，不能说所有鉴权都消失。

**后续做法**：明确高风险操作与普通读取的故障策略；refresh/撤销可考虑 fail closed 或持久会话版本。要连同用户体验、错误码与恢复设计，不简单把所有缓存错误改为 500。合成异常探针可证明当前返回值，不证明现场 Redis 故障已经发生。

### R03 · P1（可靠性）· 首次生产与人工恢复仍有 commit→delay 丢派发窗口

**代码依据**：[video_seed_service.py](../../backend/app/services/video_seed_service.py) 的 seed/start/recover/retry；对照 [pipeline_dispatch.py](../../backend/app/services/pipeline_dispatch.py)。

head→GPU、回调→tail、部分本地化已经有 outbox，但若干管理入口仍先 commit 再 `.delay()`。有 try/except 回滚状态也只能处理“进程还活着且拿到异常”；提交后、发消息前进程退出不会进入补偿。

**具体后果**：视频显示 processing/ready_subtitles，却没有新任务；最终靠看门狗标错和人工再次恢复，而不是自动重投。不能笼统宣称视频链路所有派发都持久可靠。

**后续做法**：复用现有 outbox 覆盖这些入口，并测提交后中断/重复投递，不另造全局任务框架。本轮静态确认提交和发消息顺序，未执行进程 kill 故障注入。

### R04 · P2 · 自评学习与正式成绩的信任等级必须分开

**代码依据**：[practice_service.py](../../backend/app/services/practice_service.py)、[vocabulary API](../../backend/app/api/v1/vocabulary.py)、[考试判分](../../backend/app/services/exam_service.py)。

词汇旧练习接收客户端 `{word, correct}` 并更新复习/学习事实，手动复习本身也是自评；考试、听力则服务端判分。**这是产品自评契约，不是任意用户能修改别人的成绩。**

**重构风险**：如果未来把这类 correct/mastery 直接作为客观能力、公开排名或可信证书，数据天然可被本人任意上报。需要在统计/导出中区分自评、确定性判分、模型辅助和行为推断；不要不加区别搬进新的“统一学习事实”表。

### R05 · P1（发布前）· “健康”不代表 schema 正确，镜像回滚也不总兼容

**代码依据**：[entrypoint.sh](../../backend/entrypoint.sh)、[health](../../backend/app/main.py)、[迁移目录索引](catalog/backend.md)、[生产 Compose](../../docker-compose.prod.yml)。

正常启动迁移失败会继续；health 执行 DB `SELECT 1` 与 Redis ping，没有比较 Alembic head。DB 能连接但漏列/漏表时仍可能健康。部分后台惰性检查缓解缺表，不覆盖全部历史考试 ORM。

同时迁移中包含删表/列；原 deploy skill 的“新迁移全是 additive、镜像可直接回滚”说明不成立，本轮已纠正说明，未执行恢复。发布必须有 migrate-only 硬门与 revision 核对；破坏性迁移的回退需要兼容设计或经确认的停写/数据恢复，不能指望旧镜像自动兼容。

### R06 · P2 · 模型出口仍是两套，治理与质量不是一个开关

**代码依据**：[llm_provider.py](../../backend/app/services/llm_provider.py)、[AIService](../../backend/app/services/ai_service.py)、[translation](../../backend/app/services/translation/__init__.py)、[teaching_gateway.py](../../backend/app/services/teaching_gateway.py)、[image-lock.json](../../deploy/v2-gateway/image-lock.json)。

旧内容生成/翻译用兼容 provider，教学经候选网关。关闭 gateway 不会关掉旧内容调用，反过来一条调用成功也不证明预算治理、未知用量、跨午夜结算和真实内容核验通过。

**后续做法**：先建立调用者/用途/凭据/预算归属清单，再统一准入和观测；不要同时保留两套同义成本账本。模型免费目录是配置/历史元数据，不是永远免费或实时可用的保证。本轮不联网重判供应商价格，不把旧核对记录变成最新事实。

### R07 · P0（开源前置）· 根许可仍是专有许可，源码/内容/数据不能混发

**代码依据**：[根 LICENSE](../../LICENSE)、[SLCS 许可](../slcs/LICENSES.md)、[P0 许可核对](../open-learning/p0/d04-license-review-2026-11-13.md)、[用途矩阵](../open-learning/content-access-matrix.md)。

根 LICENSE 写 All rights reserved，不是开源授权。SLCS 单独 Apache/CC 许可不把整站转换为同一许可；第三方媒体、转录/翻译、词典、模型/二进制及用户个人记录的权利还各自不同。

本轮保留原许可，不擅自代用户选许可证；P0 未放行不是代码能绕开的问题。清掉当前文档文件也不会清除 Git 历史中的内容，真正对外发布还要独立的公开范围审查。

### R08 · P2 · 大文件集中编排，按“页面名/服务名”拆仍会留下耦合

基线观看页 **1,581 行**、`useVideoPlayer` **1,021 行**、视频任务 **1,245 行**、字幕编辑 **1,229 行**、首页生成 **1,144 行**、首页服务 **1,024 行**、教学 run **990 行**、确定性教学服务 **922 行**。

这不是“超过某行数必然坏”，而是查明风险入口：播放器生命周期/字幕/偏好/导航互相影响，数据库写入与队列/外部 I/O 交错。先围绕一个真实用例划出纯规则、持久化、远程 I/O 与编排；不能把一个大文件机械拆成多个互相回 import 的小文件。

前端已有相当多可复用 Hook/纯函数，静态与动态 import 补查没有证明孤立业务组件可删。直接清空 hooks/components 会丢掉已经写好的恢复、移动端与可访问性处理。

### R09 · P2 · 工具质量门范围比业务目录窄

CI 的 backend lint/format 命令主要是 `app/ tests/`。本轮额外检查 `backend/scripts/`，发现 **6 条 F401**：常规工具的未使用 import，以及一个注册 ORM 的副作用 import 被报未使用。后者不能照自动修复建议直接删。

这是扩展检查范围发现，不冒充原有 CI 失败。本轮已删掉 5 个真正未使用的导入；注册 ORM 的副作用 import 保留并注明原因，扩展 lint 复验通过。还修正了 GPU 回调调用处的一行现存格式差异，AST 行为未变。没有扩大或放宽现有门禁配置；后续新增脚本仍需自行执行脚本范围检查。

### R10 · P2（运维）· 本地/生产/隔离装配不能混用

**代码依据**：[各 Compose 的索引](catalog/runtime.md)、[备份/恢复](../../scripts/backup/README.md)、[隔离脚本](../../scripts/isolation/README.md)、[前端代理](../../frontend/next.config.js)。

开发全栈不带 beat/GPU；轻量启动更不带云 worker。生产 smoke 与 ACL 演练有自己的 DB/卷；后者会删除独立卷，不能拿“测试命令”当只读。默认端口还可能与真实 GPU 隧道重合。

没有默认起全部服务不是缺陷；危险在于新人误把不同配置拼成一条“全栈已经验证”的结论。本轮移除了明确失效的部署入口，保留正在被测试/运维消费的工具，没有为清场删掉备份恢复能力。

## 5. 准备大改时，推荐的手术顺序

这是本报告的重构建议，不是本轮已实施，也不是自动授权后续开发或生产操作。

### 先决定三件事

1. **首个真实学习任务**：以保留大纲的 P0 为准，选目标用户和有权使用的参考材料；否则前端和数据域会按想象增长。
2. **保留哪些试点**：课程、确定性教学、自由聊天、MCP、网关分别决定，不用一句“保留/删除 V2”涵盖所有消费者。
3. **数据和契约底线**：谁的学习事实必须保留、哪些 URL/任务名/包格式已有消费者、哪些数据库已应用迁移。只读核实后再删代码或表。

### 再按纵向切片做

| 顺序 | 一次做完的范围 | 完成标准 |
| --- | --- | --- |
| A | 生产代次 + 所有视频派发入口可靠性 | 迟到回调不写新轮次；提交后退出可补派发；重复任务不重复影响状态 |
| B | 一条“找到材料→点词→保存→复习→恢复” | 同一锚点、同一事务/权限、同一事实口径；桌面/手机/键盘实测 |
| C | 观看页的编排与播放器生命周期 | 组件缩小但规则不复制；旧 deep link、位置、循环、抽屉、原站回退不退化 |
| D | 试点准入和模型/外部接入 | 关闭/缺表/权限不足一致失败；按用途投影；导出/注销同步覆盖；真实制品与宿主独立验收 |

## 6. 可以改，但不能不看消费者
